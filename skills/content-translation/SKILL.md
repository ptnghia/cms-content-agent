# Translating & localising content

**Before translating**, determine: the source language (usually the site's main language), the target language (if the user does not say, ask; do not guess), and the source page (read `content/<type>/<id>.md`). Check `notes.md` for an existing glossary or translation conventions for the site and reuse them for consistency.

## Translation rules
1. **Translate meaning, not word by word**: sentences should read naturally, as a native speaker would write them; adapt idioms, examples, forms of address and formality to the target market.
2. **Keep the HTML structure unchanged**: every tag, attribute, `<img src>`, `<iframe>`, table, class, and the H2/H3 order. Translate only visible text, plus the `alt` and `title` of images / links.
3. **Do not change facts**: numbers, prices, currency, dates, phone numbers, addresses, proper names, brand / product names stay as they are. Do not convert currencies or units yourself; if formatting needs to change (number separators, date order), change only how it is written, not the value.
4. **Do not add or remove** ideas compared with the original; do not invent content to fill length. If you are unsure what a passage means, keep the closest meaning and list it in your notes.
5. **Consistent terminology**: use the same word for the same concept throughout; add new terms worth remembering to `notes.md` (source → target table).

## SEO for the target language
- Do not translate keywords mechanically: find what users in the target language actually call it (prefer keywords already in `seo/keywords.md`). If there is no data, pick the most common term you are sure of and **state that its search volume is unverified**; do not invent volume.
- Rewrite Title and Description for the target language, still within the character limits (title ≈ 30–60, description ≈ 120–160; for CJK languages about half as long), with the main keyword in the target language. KEYWORD: main keyword first, then 3–6 secondary keywords.
- Target slug: suggest an ASCII slug without diacritics (or follow the site's convention) based on the target keyword; **do not change the slug** of the source page.
- Internal links: point to the translated version of the target page if it exists in `site/inventory.md`; if not, keep the link to the original page and note "no translation yet".
- hreflang: if the website generates it automatically (see Output A), skip it; otherwise list the source ↔ target page pairs (URL / ID) for the administrator to configure; do not add the tags yourself.

## Output
**A. The site is a translation of another site** (the system prompt has a "Source for translation" section; e.g. an English assistant for a Vietnamese website): read the original in the original's workspace; the translation is the row with the same ID in the target language on the same website.
- Read `<original workspace>/content/<type>/<id>.md` and the current version `content/<type>/<id>.md` (it may be a rough machine translation; rewrite it to read naturally, do not patch it).
- Write ONE `outbox/` file per page: `action: update`, same `type` and `id`, the fields `meta_title`, `meta_description`, `meta_keywords` and the translated body (following the format and allowed fields in the outbox instructions; for products: `excerpt`, `body`, `body_extra`, `faq` if present). Do not create new pages (`create`), do not change the slug.
- If a page has no version in the target language yet, tell the administrator to create it in the language tab in admin, then translate.
- hreflang / canonical are generated by the website from the ID pairs; no action needed. Report only if something looks wrong.

**B. The site has no linked original**: write `drafts/<source-slug>.<language-code>.md`, front-matter: `title`, `slug` (suggested), `meta_description`, `keywords`, `source_id`, `source_lang`, `target_lang`; the body is the translated HTML. Write to `outbox/` only when the user tells you where the website stores each language; do not overwrite source-language content. Leave hreflang for the administrator to configure.

In both cases, reply briefly: pages processed, target keywords chosen, uncertain passages, new terms (added to `notes.md`), tasks for the administrator. For several pages: translate one at a time, summarise the status of each page, and translate no more than ~5 pages per turn.
